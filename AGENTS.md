# AGENTS.md — working on Afterbloom

Start here if you are an AI agent (or a new human) picking up this project. Read this file first, then `DESIGN.md` (the
creative brief and the table of player notes it answers), then the code you need.

## What this is

**Afterbloom** is a first-person story game built in **Godot 4.7** (Forward+, GDScript, Jolt physics) as a Windows desktop app.
It started from the owner's handwritten notes on what they liked in the first 20 minutes of Fallout 4. The game delivers those
qualities in an **original** setting. Do **not** use any Fallout / Bethesda names, art, characters, or brands.

- **Setting:** Larkhaven, a Pacific seaside town, alternate 1967. Halcyon Electric Co. makes everything. Tuppence is the
  player's brass robot butler. A violet spore cloud, the **Bloom**, rolls in from the sea.
- **Flow:** cold open → Ch.1 *Good Morning* (cozy home) → Ch.2 *The Bloom* (dash to Shelter No. 9) → Ch.3 *Shelter* (sleep,
  11-year skip, wake, pistol, mites, restore power) → Ch.4 *Afterbloom* (reunite with Tuppence, radio, town square fight, rifle,
  coast road, Thornback boss at the lighthouse) → ending card → free roam with day/night and weather.

Everything is built from code at runtime. No `.tscn` scenes exist apart from `main.tscn` and small test scenes. Third-party
assets are CC0 Poly Haven models and textures. All other art, audio and voices are generated by scripts in `tools/`.

## Running

- **Play:** `Play Afterbloom.bat`. It runs `build/Afterbloom.exe` if exported, otherwise the project in Godot.
- **Editor:** open the folder in Godot 4.7.2 and press F5.
- **Godot CLI:** `Godot_v4.7.2-stable_win64_console.exe` is on PATH (WinGet install). Use the `_console` variant to see output.
- **First run after a clone:** run `Godot_v4.7.2-stable_win64_console.exe --headless --import --path .` once to import assets.
  This takes a few minutes.
- **Export:** `Godot_v4.7.2-stable_win64_console.exe --headless --path . --export-release "Windows Desktop" build/Afterbloom.exe`.
  - Export templates for 4.7.2 live in `%APPDATA%\Godot\export_templates\4.7.2.stable`.
  - `export_presets.cfg` includes `data/*` (non-resource files) and excludes `tests/`, `shots/`, `tools/`.

## Testing (do this; you can't play the game yourself)

1. **Compile check** loads every script:
   `Godot_v4.7.2-stable_win64_console.exe --headless --path . res://tests/compile/compile_all.tscn`.
   It prints `[compile] checked N scripts` and any `SCRIPT ERROR`s.
2. **Static screenshots** of named views (see `SHOTS` in `src/main.gd`):
   `... --path . -- --shot=home_living,street,square --shot-time=7` writes `shots/<name>.png`.
3. **Story capture with autopilot:** `... --path . -- --shot=x --story=ch2 --auto --times=10,30,60 [--shot-out=name]`.
   - `--story=` takes a checkpoint: `ch1`, `ch2`, `ch3b`, `ch4`, `ch4b`, `free`, or the test setups `test_gun` and `test_wave`.
   - `--auto` turns on the autopilot: it picks the first dialogue choice, uses interactables, takes pickups, teleports to
     objectives, and kills enemies.
   - `--times` are seconds from story start. Captures go to `shots/<shot-out>_<sec>.png`.
   - Extra arguments: `--enemy=husk|mite|thornback` (with `test_gun`, the autopilot fights it), `--gun=rifle`,
     `--wave_t=<sec>` (with `test_wave`), `--probe` (prints the real frame rate), `--timing` (prints world build stage times),
     `--hour=`, `--weather=`, `--nosky`.
4. **Viewing results:** use `tools/.venv/Scripts/python tools/montage.py out.png a.png b.png ... [--w 640]` to tile captures,
   then view the tile with an image reader. Captures are 2560x1440.
5. **Never deliver without:** a clean compile check plus an `--auto` run through any chapter you touched, with no `SCRIPT ERROR`.

**Important timing gotcha.** Building a world blocks for ~2–4 s, and shader compilation hitches for ~2 s after that. During
those first frames, `_process` barely runs. A capture taken less than ~12 s after a world build can show half-initialised
state, such as a viewmodel still mid-equip. That is not a bug; capture later. Steady state is about 58 FPS on an RTX 4060 at
1440p.

**Test mode never saves.** `Game.save_game` is a no-op when command-line test arguments are present, unless you pass
`--allowsave`. Real saves live at `%APPDATA%\Godot\app_userdata\Afterbloom\save.json`; delete it to reset Continue.

## Conventions

- **GDScript style:** typed. Avoid `:=` when the right side is a Variant (dictionary values, `.call()`, untyped arrays). Godot
  4.7 errors with "Cannot infer the type"; declare the type explicitly instead.
- **Coordinates:** +X is east (inland, toward the bluff), −X is west (the sea), −Z is north (toward the lighthouse), +Z is
  south. Yaw 0 faces north. Sea level is y=0, the town is ~5 m, the shelter gate is at y=26.
- **Physics layers:** 1 = world, 2 = player, 4 = actors, 8 = enemy hitbox Areas (with metadata `part` and `actor`),
  16 = Interactables, 32 = debris and shells.
- **Surfaces:** StaticBody3D metadata `"surface"` (`wood/concrete/metal/carpet/grass/gravel/glass`) drives footsteps and
  bullet impacts.
- **Walls:** `Geo.wall(a, b, ...)` puts `mat_in` on the **left** side of the a→b direction, viewed from above. Getting this
  backwards puts wallpaper outside, or the kitchen paper in the bedroom. Openings are `{at: distance from a, w, y0, y1}`.
- **Poly Haven models:**
  - `Props.spawn(parent, id, pos, rot_deg, {pick, collide, scale, hang, ground})`.
  - Many files are *sets*. Use `pick` with a node name; `tests/gallery` lists node names and sizes.
  - Models over 150k polygons were removed. Don't re-add the trees; they run up to 17M polygons.
- **Sound:** use `Audio.sfx("name")`. Files `name_1..N.ogg` are picked at random. Missing sounds fail silently.
- **Voice:** add a line to `data/lines.txt`, then run `tools/.venv/Scripts/python tools/gen_voice.py` (edge-tts neural voices).
  Speaker → voice mapping is in that script; speaker → audio bus and display name are in `audio.gd`.
- **Quests:** `Game.quest_start(id, title)`, `Game.objective(qid, oid, text, target_node_or_vec3, optional)`,
  `objective_done`, `quest_complete`. The HUD compass and waypoint read `Game.active_targets()`.
- **Story waits:** use the helpers `until_near`, `use_of(interactable)`, `taken(pickup)` and `until_dead(list)` rather than
  raw signals, so the autopilot works.
- **Changing the map:** edit `layout.gd` (roads, PADS, positions), then **delete `data/terrain_cache.bin`**. It is keyed by a
  hash of ROADS+PADS and rebuilds automatically, but deleting it is the safe option. Pads take an optional `"h"` (fixed height)
  and `"blend"` (metres).

## Hard-won gotchas

- **Underground spaces:** the heightmap collider pushes bodies below its surface back up. That is why the terrain
  collision has a NaN hole over `x 178..262, z -128..-68`. Keep the shelter inside it, or move the hole with it.
- **The portal pad (`blend 1.5`)** keeps the terrain slope from cutting through the shelter entry hall.
- **Viewmodels:** depth-squashing the Weapons node (`scale.z = 0.55`) stands in for a separate viewmodel FOV. A SubViewport
  approach failed because auto-exposure can't be shared. Each weapon's `hip`/`ads`/`hip_rot` live in `weapons.gd` `DEFS`.
- **Static `--shot` mode** builds the world inside `main._ready`. Story mode is the more faithful runtime; use `test_*`
  checkpoints to look at gameplay.
- **Load times:** Game preloads every model and texture on a background thread at boot. The cold open and title screen give
  it time to finish, so world builds drop from ~15 s to ~3 s.
- **Sky quality:** `SkyWeather.set_quality()` also changes global RenderingServer settings.
- **Volumetric fog:** temporal reprojection is off on purpose; with auto exposure it posterised the sky.

## Asset pipelines (all deterministic)

| What | Script | Output |
|---|---|---|
| Poly Haven models/textures | `tools/fetch_polyhaven.py` | `assets/models`, `assets/textures` |
| 2D art (magazines, posters, signs, TV cards, wallpapers, UI) | `tools/art/build_all.py` | `assets/textures/gen` (+ `ART.md`) |
| Foliage alpha textures | `tools/foliage/gen_foliage.py` | `assets/textures/foliage` |
| Music + radio songs | `tools/audio/gen_music.py` | `assets/audio/music` |
| Sound effects | `tools/audio/gen_sfx.py` (`analyze.py all` checks levels/loops) | `assets/audio/sfx` (+ `AUDIO.md`) |
| Voices | `tools/gen_voice.py` | `assets/audio/voice` |

**Python environment:** `python -m venv tools/.venv`, then `tools/.venv/Scripts/pip install numpy scipy pillow requests edge-tts soundfile`.

**Music SoundFont:** the music scripts need **GeneralUser GS v2.0.3** at `tools/audio/sf/`. It is not committed; see
`assets/audio/AUDIO.md` for the source and licence.

**Repository:** binary assets are stored with **Git LFS** (`.gitattributes`). Run `git lfs install` before cloning.

## Known issues / good next tasks

1. **No first-person hands.** Weapons float. Biggest visual gap in combat.
2. **Neighbour houses and shops are exterior shells.** Only the home, the shelter and the Civil Defense post have usable
   interiors.
3. **Tuppence moves kinematically with no pathfinding.** He can float through walls when following you out of a building;
   follow mode teleports him if he falls far behind.
4. **Story inconsistency:** June's dialogue says she shared Ward A with you, but there is no Ward B; Ward A is the only ward.
5. **Untuned by a real player:** enemy and weapon numbers (`Enemy.STATS`, `weapons.gd DEFS`) and SureShot hit chances have
   never been balanced with a human playing.
6. **Audio has only been verified by measurement:** no one has listened to it. The voices are TTS; the owner has an ElevenLabs
   account if better voices are wanted.
7. **High draw-call count (~4–9k)** because every `Geo.box` is its own MeshInstance. Merging static geometry per building
   would help on weaker GPUs.
8. **Large pack:** the `.pck` is ~830 MB. Lowering texture import sizes or compressing audio would cut it.
